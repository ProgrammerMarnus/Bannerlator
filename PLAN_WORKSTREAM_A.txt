## PHASE 1: CONTAINER REFACTOR + TESTS (PRIORITY 1)

### PROBLEM
- Container.java = 1,313 lines — mixes config, runtime state, JSON serialization, file I/O
- ContainerManager.java = 550 lines — direct file I/O, raw Thread/Executor, no abstraction
- ZERO unit tests for container logic
- Gyro migration logic embedded in ContainerManager constructor
- Import/export uses blocking I/O on background threads without structured concurrency

### SOLUTION: Split Container into 3 focused classes + Repository pattern

#### A1.1 CREATE: container/ContainerConfig.java (~350 lines)
- Immutable data class holding ALL container settings
- All current Container getters/setters → constructor parameters
- JSON serialization: toJson() / fromJson(jsonString)
- Default values as constants (mirror Container.DEFAULT_*)
- No file I/O, no runtime state, no context
- Package: com.winlator.star.container
- Must compile with Java 17 (project uses JavaVersion.VERSION_17)

#### A1.2 CREATE: container/ContainerState.java (~120 lines)
- Mutable runtime state only:
  - runningPid: Int
  - sessionId: String
  - lastLaunched: Long
  - activeWindows: List<WindowInfo>
  - currentResolution: String
- No persistence, no settings
- Package: com.winlator.star.container

#### A1.3 CREATE: container/ContainerIO.java (~280 lines)
- Static utility methods (no instance state):
  - save(Config, File) → Boolean
  - load(File) → Config
  - importContainer(srcDir, destDir, Context) → Config
  - exportContainer(Config, destDir, Context) → Boolean
  - migrateLegacyPrefs(Context, List<Config>) — extracts gyro migration from ContainerManager
  - scanContainerDirs(File homeDir) → List<Config>
- Uses existing: FileUtils, TarCompressorUtils, ImageFs
- Returns Result<T> or throws IOException (caller handles)
- Package: com.winlator.star.container

#### A1.4 CREATE: container/ContainerRepository.kt (~60 lines)
- Interface (Kotlin):
  interface ContainerRepository {
      suspend fun getAll(): Result<List<ContainerConfig>>
      suspend fun get(id: Int): Result<ContainerConfig>
      suspend fun save(config: ContainerConfig): Result<Unit>
      suspend fun delete(id: Int): Result<Unit>
      suspend fun importContainer(src: File): Result<ContainerConfig>
      suspend fun exportContainer(config: ContainerConfig, dest: File): Result<Unit>
  }
- Package: com.winlator.star.container
- Uses Result<T> for error handling (no exceptions across boundary)

#### A1.5 CREATE: container/FileContainerRepository.kt (~150 lines)
- Implementation of ContainerRepository
- Constructor: (homeDir: File, io: ContainerIO, context: Context)
- Uses coroutines (Dispatchers.IO) for all file operations
- Delegates to ContainerIO static methods
- Caches scanned containers, invalidates on save/delete/import
- Package: com.winlator.star.container

#### A1.6 REFACTOR: Container.java (1313 → ~400 lines)
- Keep public API for backward compatibility (Shortcut, XServerDisplayActivity depend on it)
- Internal delegation:
  - private val config: ContainerConfig
  - private val state: ContainerState
  - getX() → config.getX()
  - setX() → config.setX() + markDirty()
  - saveData() → ContainerIO.save(config, getConfigFile())
  - static load() → ContainerIO.load() → new Container(config, state)
- Remove all file I/O, JSON parsing, import/export, migration logic
- Keep: enums (XrControllerMapping), constants (DEFAULT_*), getConfigFile(), getDesktopDir(), etc.

#### A1.7 MODIFY: ContainerManager.java
- Add constructor: ContainerManager(Context, ContainerRepository)
- Keep no-arg constructor for backward compat (creates FileContainerRepository)
- Remove: loadContainers(), saveContainers(), importContainer(), exportContainer(), migrateGyroPrefsToContainers()
- Delegate to repository (suspend functions → run on Dispatchers.IO via CoroutineScope)
- Add CoroutineScope field (SupervisorJob + Dispatchers.Main.immediate)
- Expose Flow<List<ContainerConfig>> for UI observation
- Package: com.winlator.star.container

## PHASE 2: THREADING → COROUTINES (PRIORITY 2)

### TARGETS (raw Thread/Executor → structured coroutines)
- ContainerManager.java: Executors.newSingleThreadExecutor() → CoroutineScope
- UpdateManager.kt: Thread { } → CoroutineScope + Dispatchers.IO
- FileUtils.java: static Thread pools → CoroutineScope injection
- DownloadForegroundService.kt: HandlerThread → LifecycleScope
- UnpackService.kt: IntentService-style → CoroutineWorker (WorkManager)
- PreloaderOverlay.kt: Thread → rememberCoroutineScope

### PATTERN
```kotlin
// Before
Thread { doWork() }.start()

// After
lifecycleScope.launch(Dispatchers.IO) { doWork() }
// or
viewModelScope.launch(Dispatchers.IO) { doWork() }
// or (non-lifecycle)
CoroutineScope(SupervisorJob() + Dispatchers.IO).launch { doWork() }
```

### VERIFICATION
- No raw `new Thread()`, `Executors.`, `HandlerThread` in modified files
- All suspend functions use proper dispatchers
- Cancellation works (job.cancel() stops work)
- ./gradlew :app:compileDebugKotlin passes
